# lochin-wilde.github.io

*[English version](README.md) — основная. Этот перевод для удобства.*

Личный сайт Лочина Уайльда — композитора, саунд-дизайнера и звукорежиссёра.
Открыт по адресу **[lochin-wilde.github.io](https://lochin-wilde.github.io)**.

Три файла, без сборки и без зависимостей:

| Файл | Роль |
|---|---|
| `index.html` | Русская страница и исходник, из которого выводится английская |
| `en/index.html` | **Генерируется.** Руками не править — есть `tools/build-en.mjs` |
| `styles.css` | Оформление, подстраивается вплоть до 375 пикселей |
| `main.js` | Словари RU/EN, появление блоков, меню для узких экранов, плеер |
| `sitemap.xml`, `robots.txt` | Через них поисковик находит английскую страницу |

## Как править тексты

Правьте `index.html` и объект `translations` в `main.js`, затем выполните:

```bash
node tools/build-en.mjs
```

**`en/index.html` руками не трогать** — он генерируется, о чём написано в первой
же строке файла. Строки живут в одном месте, в словаре; русская разметка пишется
руками, английская выводится из них обоих.

Текст неизбежно существует дважды: словарь — то, что применяет скрипт, разметка
— то, что индексируют поисковики и что видно до его загрузки. Однажды они уже
разошлись: страница рассказывала про услуги веб-разработчика, а заголовок — про
композитора, и в браузере это было незаметно. Генератор нужен, чтобы вторая
языковая версия не разошлась так же.

## Язык

**Один адрес — один язык.** `/` русский, `/en/` английский, каждый объявляет
другой через `hreflang`, а переключатель RU/EN — пара обычных ссылок.

Раньше это был один адрес и скрипт, переписывавший страницу по локали браузера.
Английский текст из-за этого не попадал в поиск вообще — поисковик индексирует
адреса, а не нажимает кнопки — и посетитель с русским браузером получал русский
текст на английском адресе. `applyLanguage()` по-прежнему работает: он несёт то,
чего разметка не может, — текущий год в подвале и подписи для кнопок без текста.

## Безопасность

GitHub Pages раздаёт статику и не умеет задавать заголовки ответа, поэтому
политика безопасности содержимого едет в теге `<meta>`: `default-src 'none'`
плюс свои же CSS и JS и одно исключение — `frame-src https://w.soundcloud.com`.

**Это исключение ничего не стоит, пока им не воспользуются.** Плеера в странице
нет, есть кнопка; iframe встаёт на её место по нажатию. Посетитель, который
ничего не включал, не получает ни скриптов SoundCloud, ни их кук — страница
свободна от чужого кода по устройству, а не по обещанию. Появившийся iframe
заперт в песочницу: свои скрипты, свой источник, всплывающие окна.

На кнопке написано только «Слушать на SoundCloud». Там была строка о том, что
до нажатия ничего не грузится, — это факт про устройство, а не про музыку, и
такие фразы выдают текст, написанный машиной, а не человеком, чей это сайт.

Две защиты так передать нельзя: `frame-ancestors` и `X-Frame-Options` внутри
мета-тега игнорируются, поэтому встраивание страницы в чужой фрейм не
блокируется. На странице нет ни форм, ни входа, ни сохранённого состояния, так
что перехватывать через фрейм нечего; закрыть это по-настоящему можно только
переездом на хостинг, умеющий заголовки.

## Локальный просмотр

```bash
python3 -m http.server 8000
```

Дальше откройте `http://127.0.0.1:8000/`.

## Публикация

Публикует сам факт отправки в ветку `main`. GitHub Pages собирает из корня
ветки — настраивать и запускать нечего.
